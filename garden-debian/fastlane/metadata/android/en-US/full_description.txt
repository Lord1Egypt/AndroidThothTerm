ThothTerm • ThothDock is an independent Android application. It provides a terminal, a Debian
GNU/Linux 13 (trixie) environment to work in under PRoot, and ThothDock, a
Docker-compatible container engine for phones without root. No root, no virtual
machine, no remote server: everything runs on the phone, in the app.

The Debian side is ordinary Debian. apt and dpkg install from Debian's own
archives (trixie, trixie-updates and trixie-security), sudo is Debian's sudo,
and what you install, like your home, survives app updates.

What you get

* Debian 13 "trixie", arm64, set up on first launch
* apt, dpkg and passwordless sudo for the user thoth
* Several terminal windows, pinch-to-zoom, an extra keys row, copy and paste
* Correct Arabic and other right-to-left text
* ThothDock: the Docker command line, working on the phone, with no root
* Docker Compose, user networks with container names, restart policies
* Containers, Images and Volumes screens: start, stop, logs, shell, delete
* Flatpak apps and snaps, run by ThothDock and listed in an Apps screen
* A Web Panel to manage containers from a browser, over HTTPS with a pairing code
* LAN Mode, to use the same Debian from a web browser on another computer

ThothDock

ThothDock is a Docker-compatible container engine written for unrooted
Android. The unmodified Docker command line talks to it over a private socket
that only this app can open, so docker pull, run, exec, logs, stop, volumes,
-p port publishing and docker compose work from the terminal. There is no
dockerd: containers run through the same PRoot that runs Debian. Containers
on a user network get a private loopback address and reach each other by name.

Containers are userspace environments, not a security boundary: there are no
namespaces and no resource limits. A published port is a loopback listener
that every app on the phone can reach; UDP publishing is not supported.
Containers stop when the app is closed. Images are downloaded only when you run
docker pull or docker run, never in the background. Android may end the engine
when too many processes run; the Containers screen warns first. Engine
Guard stops apt replacing ThothDock with a real Docker engine.

Flatpak and snap

Debian's flatpak works: ThothDock runs its sandboxes, as bubblewrap needs root.
The snap command installs from the Snap Store and runs apps and services; it
contacts the store only when you run snap find, info or install. Each app or service gets its own loopback address. Snap confinement
and Flatpak sandboxing are not enforced, as with containers.

Web Panel and LAN Mode

Both are off until you turn them on and never listen on mobile data. The Web
Panel serves HTTPS only, on the phone itself or on Wi-Fi or Ethernet; a browser
must enter the pairing code shown on the phone, and its sessions end when the
panel stops.
LAN Mode gives each paired browser its own terminal after a one-time PIN. Its
connection is plain, unencrypted HTTP: use it only on networks you trust.

First run

The F-Droid build does not include Debian, so the first launch offers to
download it: about 60 MB from the project's GitHub release. Nothing is
downloaded until you agree. The download is checked against a size and a
SHA-256 checksum written into the app, and refused if either differs. The
archive holds only unmodified Debian packages, built reproducibly by a script in
the app's source.

Requirements: a 64-bit ARM phone (arm64-v8a) with Android 8.0 or newer, and
about 185 MB for Debian after setup.
